An interactive accessibility exhibit

At 4× zoom, you see one sixteenth of the screen.

Millions of people browse the web through a screen magnifier, browser zoom, or larger default text. The design choices that look tidy at 100% can quietly break at 400%. Try it for yourself at the three stations below.

2.2 billion people worldwide live with a near or distance vision impairment (World Health Organization). Even more people zoom in because of tired eyes, small screens, glare, or age.

02

Zoom to 400%

Browser zoom makes the viewport effectively narrower. On a 1280px-wide window, 400% zoom leaves a layout with just 320 CSS pixels, the width of a small phone. A layout with a fixed width makes people scroll sideways on every line. A responsive one reflows.

03

Turn up the text

Many people never touch the zoom shortcut. They set a larger default font size in their browser or operating system instead. Text sized in fixed pixels ignores that setting, and boxes with fixed heights cut off text that does grow.

04

Design for the zoomed-in view

Most of these fixes cost nothing if you build them in from the start.

  1. Keep feedback close to the action

    Put errors next to the field they describe and confirmations next to the button that triggered them. Don’t rely on corner toasts or top-of-page banners alone.

    WCAG 3.3.1 Error Identification · 4.1.3 Status Messages

  2. Reflow at 320 CSS pixels

    At 400% zoom, content should fit in one column with no horizontal scrolling. Use fluid grids, flex-wrap, minmax() and container or media queries.

    WCAG 1.4.10 Reflow (AA)

  3. Size text in relative units

    Use rem and em for type and spacing so text follows the reader’s chosen size. Make sure it still works when text is enlarged to 200%.

    WCAG 1.4.4 Resize Text (AA)

  4. Let boxes grow

    Prefer min-height over height, and avoid overflow: hidden or nowrap on text. Allow extra line, letter and word spacing.

    WCAG 1.4.12 Text Spacing (AA)

  5. Never disable pinch-zoom

    Remove maximum-scale=1 and user-scalable=no from your viewport meta tag.

    WCAG 1.4.4 Resize Text (AA)

  6. Watch sticky headers and footers

    When the page is magnified, sticky bars can fill most of what’s visible and hide the focused element. Keep them short, or un-stick them on small viewports.

    WCAG 2.4.11 Focus Not Obscured (AA)

  7. Make hover content behave

    Tooltips and menus must stay open while the pointer moves onto them, and must be dismissible with Esc. A magnifier user moves slowly.

    WCAG 1.4.13 Content on Hover or Focus (AA)

  8. Use real text, not pictures of text

    Text in images turns blurry when enlarged and can’t reflow or change color.

    WCAG 1.4.5 Images of Text (AA)

Test it yourself in five minutes

  • Ctrl/⌘ + + zoom your browser to 400% and use the page.
  • macOS Zoom: ⌥ ⌘ 8 (turn it on in System Settings → Accessibility → Zoom).
  • Windows Magnifier: ⊞ Win + +; exit with ⊞ Win + Esc.
  • Set your browser’s default font size to “Very large” and check that nothing clips.
